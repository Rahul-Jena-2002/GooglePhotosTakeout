# TakeoutFix AdSense Readiness Audit

Audit basis: repository source on `main`, reviewed 16 November 2026. This report does not include live Search Console, Analytics, AdSense, Cloudflare, or production checks. No AdSense approval is guaranteed.

## Summary

The strongest evidence-backed improvements are to make indexing reflect page purpose and to remove unsupported product promises. The site already has useful guides, a restore walkthrough, an about page identifying the independent maintainer, a contact address, privacy and terms pages, and local browser processing code. This pass added static support guidance, a plain-language verification tutorial, and removed the homepage's empty stats/social-proof section and its unused data fetches. Remaining quality risks include broad claims elsewhere about format support and desktop-app capabilities that need a separate verification pass.

## Verified product capabilities from source

| Capability | Evidence / actual scope | Limits to communicate |
|---|---|---|
| Filename matching | `MetadataMatcher.ts` allowlists JPG/JPEG, PNG, GIF, WebP, TIFF/TIF, MP4/MOV/HEIC/HEIF/M4V/AVI/MKV/3GP/3GPP/DNG and generates sidecar candidates, including normalization/truncation patterns | Candidate match support does not establish successful write support for every extension; ambiguous/missing sidecars can prevent restoration |
| ZIP sidecar matching | `ZipMetadataMatcher.ts` normalizes paths and names, supports hash suffix and truncated candidates | Does not prove every ZIP structure or archive size is supported |
| Image metadata writing | `ExifRestorer.ts` delegates to `DeepExifRestorer.ts` / WASM ExifTool and returns failure with original bytes on error | Need inspect the deep writer and worker callers for per-format write support before making a compatibility promise |
| Video timestamps | `VideoMetadataRestorer.ts` edits `mvhd`, `tkhd`, and `mdhd` atoms in MP4/MOV/M4V containers | It changes container creation/modification timestamps; it does not establish support for all video extensions accepted by the matcher or restore arbitrary video metadata |
| Privacy | The restore code is browser/worker based; tool UI says selected media is not uploaded. Site separately uses Firebase, Sentry, EmailJS and AdSense integrations | Do not say that no information ever leaves the browser; privacy page must describe non-media services |
| Original preservation | UI describes output to a chosen location; confirm each processing path before making an absolute guarantee | Tell users to keep their own untouched archive and verify sample output |

## Technical SEO and monetization findings

- Shared layout emits a canonical, robots directive, meta description, Open Graph and Twitter metadata. Page-specific title and description coverage is generally present.
- Sitemap generation is a hand-maintained allowlist. Updated pages now have explicit last-modified dates. Useful contact, support, download and policy pages are included and remain accessible through navigation.
- `robots.txt` allows general crawlers and the explicitly named AI search crawlers to access the noindex dashboard and profile shells so they can see those directives. Admin and API paths remain disallowed; robots rules are crawler guidance, not access control. Verify these directives on the deployed site using Search Console and relevant crawler documentation.
- Curated keyword pages remain noindex and outside the sitemap. Their before/after is now labeled illustrative, and several unsupported promises in the shared content and page introductions have been qualified. Render and review all variants before release; these changes do not establish search indexing.
- Astro uses Cloudflare adapter with server output. A build-time SPA rewrite script and `public/_redirects` should be checked against the actual Cloudflare Pages deployment behavior before infrastructure changes.
- AdSense loader is included once in the shared layout, with the publisher verification meta tag and `ads.txt` present. This source review cannot verify publisher account, live ad placement, or consent behavior in production.
- Support remains client-rendered, but its initial fallback now contains troubleshooting guidance and a contact address.

## Release blockers and remaining checks

- Exercise image and video restoration with representative Takeout archives, missing or ambiguous sidecars, duplicate filenames, failed metadata writes and interrupted output. Check both folder and ZIP downloads against the report and original files. In particular, validate the new serialized filename reservation under concurrent folder processing; it coordinates only within one processing run, not separate tabs or processes.
- Worker results are now rejected when they lack a valid nonempty buffer or explicit success status, instead of falling back to a potentially detached transferred buffer. The unused synchronous EXIF compatibility function no longer reports an unchanged file as restored. Verify worker failures and metadata fallbacks in browser tests.
- The post-processing summary can also appear after cancellation or failure, so it no longer claims all dates and locations were restored or labels every stopped run complete. Verify its timing and counts for completed, cancelled, quota-limited and failed runs; it still needs an explicit outcome state.
- The restore UI now remains in its processing state until completion finalization exits, and ignores cancellation once that finalization has begun. Previously it could offer another run while reports and session records were still being written. An uncaught finalization error now reports failure in the UI; individual report and history writes that already catch their own errors still need review. This lifecycle change is untested; verify failed writes, cancellation, ZIP downloads and attempts to start another run, and review other early-stop paths before relying on it.
- Cancellation now marks the run stopped, terminates its worker pool and waits for tracked in-flight file tasks before closing ZIP output and finishing its bookkeeping. Queue fetches now check a run generation before dispatching or finalizing, reducing the chance that an old queue resumes during a later run. These changes are untested; verify queue fetch races, task rejection, stalled writes, cancellation, partial output and subsequent runs in an isolated browser before relying on them.
- Restore startup and resume now reject duplicate requests, and cancellation waits for an ongoing scan or resume setup before cleanup. Test repeated clicks, cancellation during each startup stage, blocked reads and restarting after cancellation; these paths have not been run.
- A quota stop now schedules cleanup outside the file task that detected the limit, stops workers and waits for tracked tasks before releasing the controls. This avoids waiting on the detecting task itself, but has not been tested. Verify concurrent quota checks, stalled writes, ZIP output, counts and restart behavior; quota enforcement remains client-controlled.
- ZIP packaging failure now keeps the controls busy while tracked file tasks settle and the session is marked failed, and its message does not assume whether the browser saved a partially triggered download. Test failures during chunk rotation and final packaging, task settlement, session errors and retries; this path is unrun.

### Restore lifecycle validation cases

Run these only in an isolated browser environment with no external network and disposable source and output folders. Use small, synthetic media and sidecars; keep an independent checksum of every source file. The current environment does not provide the isolation required to run them.

The existing `scripts/test_mobile_playwright.js` serves a built `dist` directory and takes a screenshot; it does not cover these lifecycle cases. `scripts/run_validation_tests.js` sends requests to local payment and webhook endpoints, so do not point it at a server connected to live payment or Firebase services.

1. **Normal folder output:** Restore a matching file, an unmatched file and a file that causes an output error. Check the report against the actual output and confirm source checksums are unchanged. Start a second run only after final reports and session updates finish.
2. **Duplicate start and startup cancellation:** Trigger both start buttons quickly, then repeat while cancelling during folder scanning. Confirm only one session owns the output, a cancelled scan cannot start processing later, and a later run does not receive records from the cancelled scan.
3. **Cancellation during writes:** Delay a file write and cancel. Confirm the controls remain busy until active tasks settle, inspect any partial output and logs, then start another run and verify its counts and output are independent.
4. **Quota stop:** Reach the guest limit with multiple files in flight. Confirm the stop waits for tracked tasks, does not claim untouched files were processed, and leaves the originals unchanged. Check folder and ZIP modes separately.
5. **ZIP packaging failure:** Force archive close or download initiation to fail both during a chunk rotation and at the final chunk. Confirm the failure is visible, the session is marked failed, and a later run cannot start until cleanup exits. Inspect earlier downloads separately; a browser download request is not proof of a saved file.
6. **Stalled and rejected operations:** Hold an output write or session update open, and separately reject it. Confirm a pending operation does not release the controls early, failures are visible, and no run is reported as fully successful when work remains unresolved.
- Interrupted-run cleanup no longer deletes a filename it cannot prove belongs to the run; a retry may leave an extra output instead. Folder source and destination must now be separate and non-nested, and guest session creation no longer dereferences a missing user. Verify guest and interrupted recovery paths before release.
- Output-name selection no longer treats a failed renamed-file creation as permission to retry the original name. `tests/output-file.test.mjs` covers that failure and ordinary collisions; the existence check remains non-atomic against other tabs or processes, and the tests have not been run.
